# Техники реализации подсветки и силуэта существ (Outline & Silhouette) в Valheim

В данном документе рассматриваются технические способы создания контура и эффекта видимости силуэта монстров сквозь препятствия в движке Valheim (Unity Forward+ / Deferred / SRP), а также выбор наиболее стабильного решения без падения FPS и утечек памяти.

---

## 1. Сравнение подходов к подсветке в Unity/Valheim

### Подход 1: Пост-процессинг через CommandBuffer / Custom Stencil
* **Суть:** Добавление вторичного рендер-прохода (RenderPass) через камеру Unity с маской трафарета (Stencil Buffer) и шейдером размытия контура (Sobel / Jump Flood).
* **Минусы для Valheim:**
  - В Valheim используется кастомная связка шейдеров освещения и тумана. Вмешательство в пайплайн камеры часто конфликтует с модами на графику (HD Overhauls, Valheim Plus, Camera tweaks).
  - Требует дополнительных буферов рендеринга и создает ощутимую нагрузку на GPU на слабых видеокартах.

### Подход 2: Модификация материалов через `renderer.material`
* **Суть:** Попытка напрямую подменить шейдер у рендерера монстра.
* **Минусы:**
  - Приводит к `Instantiating material` в Unity. Каждый пинг создает новый объект в куче, порождая сборку мусора и лаги (GC Spikes).
  - При убийстве монстра или выходе из зоны прорисовки оригинальный материал может потеряться.

### Подход 3 (Рекомендуемый и принятый): Гибридная система `MaterialMan` + Silhouette X-Ray Pass

Данный подход совмещает два легковесных, 100% совместимых и надежных метода:

#### Шаг А: Эмиссионное свечение через ванильный `MaterialMan`
Valheim уже имеет встроенную поддержку управления свойствами шейдеров без создания дубликатов материалов:
```csharp
// Задаем цвет и интенсивность свечения через MaterialPropertyBlock:
MaterialMan.instance.SetValue(character.gameObject, ShaderProps._EmissionColor, highlightColor * 2.5f);
```
Это заставляет модель монстра пульсировать ярким неоновым цветом выбранного оттенка пинга прямо в 3D-мире.

#### Шаг Б: Силуэтная видимость сквозь стены (X-Ray Overlay)
Чтобы силуэт монстра был отчетливо виден за деревьями, камнями, горами и в темноте (как просил пользователь):
1. На объект `character.gameObject` временно навешивается легковесный компонент `CreatureHighlighter`.
2. Создается упрощенный контурный рендерер с шейдером, у которого параметр `ZTest` установлен в `Greater` (или используется полупрозрачный силуэтный оверлей):
   - Если монстр закрыт скалой или деревом — рисуется его светящийся цветной силуэт поверх преграды.
   - Если монстр в прямой видимости — видно его обычную модель с ярким эмиссионным свечением.
3. По истечении таймера (15–20 секунд) или при смерти монстра (`character.IsDead()`):
   - Вызывается `MaterialMan.instance.ResetValue(character.gameObject, ShaderProps._EmissionColor)`.
   - Силуэтный оверлей уничтожается.
   - Память полностью чиста.

## 2. Динамическое следование 3D-маркера за головой монстра

Обычный пинг ставится в статические мировые координаты (`Vector3`).
Но если задетектирован монстр:
* Маркер привязывается к Transform головы:
  ```csharp
  Vector3 markerPos = character.GetHeadPoint() + Vector3.up * 0.4f;
  ```
* В цикле `Update()` позиция маркера плавно интерполируется за движущимся монстром.
* В UI выводится имя существа, его уровень (звездность) и полоска/процент здоровья:
  ```csharp
  string title = $"{character.GetHoverName()} (★{character.GetLevel()})";
  ```
* Если монстр убит игроками раньше времени — метка мгновенно переходит в статус «ликвидирован» и плавно исчезает.
